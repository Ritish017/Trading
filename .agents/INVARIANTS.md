# APEX Quant Lab — Engineering Constitution & Invariants

This document establishes the canonical non-negotiable invariants for APEX Quant Lab. Every agent (ChatGPT, Antigravity, or human contributor) must uphold these rules without exception.

---

## The 15 Core Invariants

1. **No Fabricated Financial Data**
   - The platform never fabricates or hallucinates financial data, ticker quotes, or order-book states.
   - If real market data is unavailable, the system reports explicitly that data is absent or disconnected.

2. **No Synthetic Current Prices**
   - Live/current market prices displayed in UI or used in live strategy triggers must originate exclusively from verified broker/feed data (e.g., Upstox REST/WebSocket).
   - No mock random walks or mathematical simulations may masquerade as live current prices.

3. **Missing != Zero**
   - A missing data point, null field, or absent financial statement item is strictly treated as `None` / `null` / `missing`.
   - Never substitute `0` or `0.0` for missing prices, volumes, returns, or accounting figures unless mathematically proven to be zero.

4. **Mock != Live**
   - Mock data providers and live broker feeds must be isolated by strict domain boundaries, explicit typing, and distinct visual tags (`[MOCK]` vs `[LIVE]`).
   - Mock states must never leak into live execution, live paper trading, or live auditing records.

5. **Provider Timestamp is Authoritative**
   - The timestamp generated by the exchange/feed provider (`provider_timestamp`) is the authoritative reference for market events, candles, and tick ordering.
   - Client receipt timestamp (`received_timestamp`) is logged strictly for latency and freshness diagnostics.

6. **Frontend Does Not Calculate Financial Indicators**
   - All quantitative indicators (RSI, MACD, Bollinger Bands, ATR, Supertrend, etc.), signals, and risk analytics must be computed in the backend Python Quant Engine.
   - The frontend React application acts solely as a presentation and interaction layer.

7. **Quant Engine is Canonical**
   - The backend Python Quant Engine (`backend/app/strategy_engine/`, `backend/app/market_data/`, `backend/app/intelligence_engine/`) is the single source of truth for all quantitative formulas, backtesting, and forward validation.

8. **Strategy Activation != Trade**
   - A strategy condition trigger or rule activation event signifies only that a quantitative criteria was met.
   - It is NOT an executed order until evaluated by Risk Management and processed through the Order Lifecycle Manager.

9. **Historical Observation != Backtested Performance**
   - Observing historical patterns or past candle sequences does not constitute backtested strategy performance.
   - Backtest results require complete trade simulation with explicit order execution, slippage, and fees.

10. **Backtest != Live Performance**
    - Backtest returns are strictly hypothetical simulations.
    - They must never be represented as guaranteed or live performance, and must include in-sample/out-of-sample (IS/OOS) validation and overfitting classification.

11. **No Lookahead Bias**
    - At any simulated timestamp $T$, the strategy and indicator pipelines may ONLY access information known at or before $T$.
    - Future candle bars, future corporate actions, or restated financial statements must never leak into historical evaluation.

12. **Corporate-Action Adjustment Does Not Modify Current Live Prices**
    - Split, bonus, or dividend adjustments apply strictly to historical series for continuity.
    - Current live spot prices must reflect the actual unadjusted traded price on the exchange.

13. **Fundamental Data Must Be Point-in-Time (PIT)**
    - Financial statement metrics and ratios must be indexed by their public filing/disclosure timestamp (`publication_timestamp`), not merely the fiscal period end date (`period_end`).

14. **Paper Trading Uses Canonical Market Data**
    - Paper trading accounts and simulated order matching must use the exact same canonical market data stream and pricing engine as the live monitoring system.

15. **Every Research Result Requires Provenance**
    - Every backtest metric, research finding, factor score, and strategy recommendation must record complete provenance: dataset hash, parameter dictionary, code commit, execution timestamp, and assumptions.
